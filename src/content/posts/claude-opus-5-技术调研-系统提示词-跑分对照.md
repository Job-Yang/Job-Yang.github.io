# 把系统提示词和跑分对起来看

先看外部表现：SWE-bench Pro 从 69.2% 拉到 79.2%，Frontier-Bench 翻倍，OSWorld 靠约三分之一成本压过更贵的 Fable 5[［Claude Opus 5 vs 4.8］](https://codersera.com/blog/claude-opus-5-vs-opus-4-8-2026/)。

这次流出的材料是第三方抓取的 claude.ai 网页端系统提示词（`github.com/Eversmile12/leaked-llm-prompts` 于 2026-07-24 采集，另有 `asgeirtj/system_prompts_leaks` 同日独立收录可交叉对证）。提示词改不了模型权重，但它就是行为层面的操作系统；同样的底座换一套行为编排，长任务表现能拉出一大截。

```
                  ┌─────────────────────────────┐
                  │   模型权重（不公开，看不到）   │  ← 底座推理与自我纠偏能力更强
                  └──────────────┬──────────────┘
                                 │
                  ┌──────────────▼──────────────┐
                  │   系统提示词（本次可对照部分）  │  ← 默认思考、记忆系统、草稿区、安全路由
                  └──────────────┬──────────────┘
                                 │
                  ┌──────────────▼──────────────┐
                  │   外部公开跑分与真实体感       │  ← SWE-bench / Frontier-Bench / OSWorld
                  └─────────────────────────────┘
```

# 提示词里最值得看清的六处设计

## 把先想再答做成默认开关，配上用力档位

Environment 段明文要求模型不管问题表面多简单，只要有一点复杂迹象就默认走扩展思考，不许光凭熟悉感瞎蒙。

这就是推理时算力（test-time compute）：前代 Opus 4.8 默认不额外深想，Opus 5 改成默认开启，再叠上 low、medium、high、xhigh、max 五个用力旋钮[［MarkTechPost］](https://www.marktechpost.com/2026/07/24/meet-the-new-claude-opus-5-frontier-class-agentic-coding-and-computer-use-at-unchanged-opus-pricing/)。长链条且需反复核验的榜单涨幅最高（比如 SWE-bench Multimodal 从 38.4% 跳到 59.4%），而 xhigh 档能比 max 少用 25% token 依然拿头名。

## 把持久记忆做成一个「文件系统」

整份材料里最像写操作系统的一段，直接给了五条带权限控制的读写命令：

| 记忆接口 | 核心作用 |
|-|-|
| `memory_read(path)` | 一次最多读 20 个文件，返回正文和版本令牌 |
| `memory_write(path, content, if_version)` | 建文件或全量覆盖写，带版本冲突校验 |
| `memory_str_replace(...)` | 局部替换文件片段 |
| `memory_append(...)` | 向文件末尾追加记录 |
| `memory_delete(...)` | 删整份文件，仅允许用户明确发话时调用 |

接口背后配了四条颇具工程味的规定：

- **带版本令牌的乐观锁（`if_version`）：**明确考虑到多个载体并发改同一个记忆文件，提前堵住写入覆盖冲突。
- **以「给下个自己交接班」的心态写：**要求写进下一个 session 开场时自己最需要提前知道的背景。
- **禁靠猜测回答「没有」：**特别点名没读过 `/people/sister.md` 就直接回「我不知道你姐妹信息」，属于自信的瞎编。
- **按来源打三档可信标签：**区分用户亲口说 `[stated]`、观察 `[observed]` 和推论 `[inferred]`，且模型自身只允许写 `[stated]`。

长周期任务（longer-horizon work）里最见效的就是这套文件系统：比如生产监控 Agent 排查完误报，能自己把纠正写回持久记忆并退订冗余查询[［Anthropic 发布页］](https://www.anthropic.com/news/claude-opus-5)。

## 动手前无条件先读 SKILL.md 手册

> 「在编写任何代码、创建任何文件之前，阅读相关的 `SKILL.md` 是必需的第一步……因为技能里写死了特定环境下的可用库、渲染怪癖与输出路径，跳过阅读即便在熟悉格式上也会拉低质量。」

而且提示词禁掉了「先自己判断需不需要看技能」，改成无条件先查。预训练记忆装的是过去的通用知识，当下环境的真实限制全靠本地手册强行覆盖，这解释了 SWE-bench Multimodal 为什么能明显拉高。

## 工作流切出「草稿区」和「交付区」

工作目录被分成三块，完全照着资深开发的桌面习惯来：

1. `/mnt/user-data/uploads`：用户上传文件区（只读）
2. `/home/claude`：内部草稿区（scratchpad），试错、写草稿全放这儿，用户看不见
3. `/mnt/user-data/outputs`：只用来放最终交付结果

对超过 100 行的长任务还强制「大纲 → 逐节写 → 自检精炼 → 复制到 outputs」。

难怪用户反馈 Opus 5 写出的 diff 更干脆、少了死代码[［Anthropic 发布页］](https://www.anthropic.com/news/claude-opus-5)：过程脏乱留给后台草稿区消化，摆到桌面的永远是洗干净的成稿。

## 引用机制：只用于归属，禁止整段照抄

- 每条具体结论用 `<cite index="DOC-SENTENCE">` 精准挂到原文档某一句或多句上。
- 硬规定「主张必须用自己的话重写，严禁逐字抄原文」：引用标签是给事实标归属，不是授权直接复制大段文字。

这一设计同时搞定事实可溯源和版权规避。

## 安全机制：判整场累积，还能降级路由

安全段的设计明显比关键词过滤高出几截：

- **整场对话累积评估：**明文要求不要孤立看单轮提问，只要整场对话拼起来接近危险方案或攻击脚本，哪怕上个会话摘要看着无害也必须停手，专防分步试探绕过。
- **把「自我辩解重框」当停手信号：**儿童安全准则里有一句很值得学：一旦模型发现自己在心里重新解释请求以显得合规，这个自我说服的念头本身就是该拒绝的信号。
- **路由自动降级：**面对复杂边缘请求，安全机制触发后不再一律粗暴硬拒，而是按策略走安全路由。这也顺手呼应了一个对比数据：同一轮 Frontier-Bench 测试中 Fable 5 有 42% 请求被安全策略误伤，Opus 5 降到 5%[［MarkTechPost］](https://www.marktechpost.com/2026/07/24/meet-the-new-claude-opus-5-frontier-class-agentic-coding-and-computer-use-at-unchanged-opus-pricing/)。

# 两半拼在一起看：为什么拉出跨代差距

以前把思考做成可选、对话记成一次性、环境规矩赌进预训练、安全拦截停在单轮，一跑长链路 Agent 误差就复利般滚大。

Opus 5 这边是两件事乘在一起发力：权重自己更扛长程推理与自检（看不见），提示词层顺手补上默认思考、草稿区、持久记忆和少误伤（看得见）。

二者缺一不可：把同一套提示词套给弱模型照样跑不动；反过来有了好底座再配顺滑的工作流规范，Agent 类长任务自然涨幅最猛，而一问一答知识题涨幅就温和得多。

# 界线在哪里（读这份材料前要先留神）

- **提示词出自 claude.ai 聊天端，而非裸 API：**自己调 API 写 system prompt 时不会自动带上这套记忆文件系统和强制先读规则，消费级产品的好感体验不能直接全归功于模型 API。
- **解释不了权重层本身的进步：**底层推理为什么更强、训练用了什么新方法，官方没有公开，看系统提示词推断不出模型内部架构。
- **泄露内容交叉吻合度高，但仍未获官方证真：**两个独立仓库 `Eversmile12` 和 `asgeirtj` 在 2026 年 7 月 24 日同天采集到一致版本，其中的 Mythos 层级、Project Glasswing 代号、Fable 5 的 \$10/\$50 定价也与官方口径吻合；严谨来说仍属第三方社区抓取，需保持「据泄露材料」口径。
- **第三方跑分口径存在波动：**例如 SWE-bench Verified 有的报 96%、有的报 97%，各家评测 harness 不尽相同，重点看相对趋势而不是抠死单个小数点。

# 对做 Agent 工程可以直接带走的五点

1. **把上下文当长期资产经营：**记忆做成带版本号、来源标签和局部修改接口的文件系统，才能让下一个 session 接上力。
2. **环境规矩用外挂手册盖住模型旧记忆：**把库版本和输出目录写进 `SKILL.md` 强制先读，比微调划算且跟得上变动。
3. **在内部划分草稿区和交付区：**中间试错允许乱，交给用户的终稿必须清爽。
4. **把安全和质量放进整场对话累积评估：**防绕过、防越跑越歪都看全局轨迹，别只盯孤立一轮。
5. **提供可调节的思考档位开关：**简单活开低档省成本，难题拉高档扛住准确率。
