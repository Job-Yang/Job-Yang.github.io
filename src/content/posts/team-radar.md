# 背景与痛点

AI 编程已经很强，但很多团队依然反复出现线上卡顿、隐蔽的交互退回、发版返工和排队等待；**先发现真正卡在哪**，往往比动手修改更稀缺。

- **数字表格抓不住重点**：几十个页面、上百条指标铺在表格里，很难一眼扫出哪里掉得最狠、是不是某次改配置带偏。
- **传统监控看不出体验卡壳**：服务端接口零报错、崩溃率为零时，用户可能正在被强弹窗打断、流式卡片等不及关掉、或频繁手动修改 AI 识别结果。
- **需要贯穿进组前期和中后期**：前两周用来快速摸清主链路和交付里的主要堵点，找准切入点；稳定后按天或按周定时跑一遍，充当业务转化和研发效率的双重巡检雷达。

# 方案定位与边界

Team Radar 聚焦 **发现卡点 + 定位代码 + 交接 AI** 这三件事，不重造重型平台，也不越界直接改业务线。

| 对比维度 | 常规监控与报警 | 通用 BI 报表大盘 | 自动修复代码代理 | **Team Radar（本方案）** |
|-|-|-|-|-|
| 关注重点 | 崩溃率、接口耗时与错误率 | 业务流量与转化数字 | 自动改源码与提交修复 | **交叉看转化、崩溃与返工** |
| 体验卡壳可见性 | 看不见零报错但高退回的场景 | 表格与折线为主，定位不到按钮 | 无交互看板 | **仿真手机视图**点按钮看埋点 |
| 改动对比能力 | 改动记录与指标系统通常分离 | 看板与发布单分处不同系统 | 仅盯代码仓 | **同轴叠加发版、配置与实验** |
| 与 AI 的衔接 | 需人工复制堆栈和业务背景 | 需人工截图整理给大模型 | 缺少业务意图易误改 | 输出 **3 步清单与完整提示词** |
| 换公司携带成本 | 高度绑定特定监控平台 | 强依赖内部数仓与看板系统 | 依赖公司内部权限体系 | **零三方依赖，换公司即用** |

# 四个独立视图设计

旧版单屏塞满卡片互相抢空间；新版拆成 4 个顶层页签，各自占满一屏且共享 **P0-P2 优先级清单**，重点不漏、次要不挤。

| 页签名称 | 面向谁、看什么 | 核心展示与交互设计 | 能直接解答的问题 |
|-|-|-|-|
| 总览 | 负责人与全组每日第一眼 | 上方 4 格战情条突出高危告警；下栏左列排最该先处理的 4 件事，右列放近 7 天趋势摘要与耗时分布 | 今天最急的是哪一两件事？该去查页面、改动还是效率？ |
| 页面转化 | 端侧、AI 交互与产品同学 | 左侧画全链路流向（切换全部/转化/崩溃卡顿/卡壳改错、按人数或次数统计）与 3 维人群对比；右侧挂**仿真手机屏幕** | 是哪个入口、哪档机型、还是手机里哪一个按钮拖垮了转化？ |
| 上线变动 | 发版值班、策略与算法同学 | 双轴折线同画转化率与 P90 耗时，虚线标每天改动；支持按远程配置、灰度、Prompt、AB 实验筛选 | 转化或耗时是从哪一天、哪一次上线改动后开始掉的？ |
| 交付效率 | 研发负责人与 TL | 上方 3 格摘要损失；中栏用趋势柱条标出各小组按期率（跌破 85% 且环比跌超 15% 标红）；下栏看热修文件与月耗人天 | 研发时间主要耗在哪？哪些小组和文件上线后反复返工？ |

- **平实直观，不造生僻词**：界面删掉各类术语包装，退回就是退回、手改就是手改、连续大幅下跌再标红，减少误报干扰。
- **暗色与暖骨白双主题**：默认深碳底精密仪器配色，支持一键切换暖骨白高对比模式；导出单文件离线 HTML，内网浏览器双击即开。

# 多公司渐进取数方案

每家公司的看板、日志与发布系统各不相同，本方案只认统一的 **`snapshot.json`**，让核心分析和前端在不同公司零重写直接复用。

| 档位 | 数据来源怎么接 | 适合什么时候用 | 维护成本与改前端代码吗 |
|-|-|-|-|
| 第一档：手工导表或转格式 | 从现有看板导出近 7 天转化、崩溃、改动与排期 CSV，整理成 `snapshot.json` | 进组第 1 天到第 2 周，尚无跨平台接口权限时快速摸底 | **10 分钟跑通**，无需改分析与前端 |
| 第二档：本地只读脚本定期汇总 | 用只读脚本拉 Git 近 7 天热点返工、构建耗时与导表结果自动更新快照 | 日常周巡检或发版前后对比 | 全走本地定时脚本，不改前端 |
| 第三档：内部看板、APM 与 MCP | 条件成熟后接内部只读接口或 MCP 插件，每天定时写入 `snapshot.json` | 团队长期日常自动巡检与早预警 | 仅加前置读取插件，**核心零改动** |

# AI 辅助排查交接

找到异常只是第一步；Team Radar 通过 **3 步排查清单 + 可带走上下文包**，帮助成员把异常无缝交给自己习惯的 AI 编程工具继续深挖。

1. **只给线索清单，不越权乱改**：每条异常附带可疑代码或配置路径、日志过滤条件与建议优先核查的 3 个步骤，点击可打勾标记进度。
2. **网页与命令行双导包入口**：看板任意位置点开「AI 排查」抽屉可一键复制整份 Markdown 包（附无剪贴板权限时的备用复制框）；终端也能用 `build_radar.py --export-prompt <问题ID>` 直接输出。
3. **自动拼齐关键背景**：上下文包内置当期数据变化、同期线上改动与三维度差异，AI 一读即懂前因后果，不必人肉跨四五个网页截图拼接。

# 运转机制与仓内协作

**`team-kit` 同仓收纳**两个独立模块，日常用 `radar/` 找卡点、交给 AI 查源码，解决完再顺手把经验补进 `context/`。

![图 2：Team Radar 日常运转闭环](/assets/content/team-radar/sync-02.webp)

读图提示：`team-kit` 把「Radar 发现卡点 -> AI 查代码定位 -> Context 沉淀避坑」串成一个闭环，既减少重复踩坑，也让团队知识自然保鲜。

在仓库组织上，`Team Context` 与 `Team Radar` 统一并入 [team-kit](https://github.com/Job-Yang/team-kit) 同仓管理，两个模块相互独立、低耦合联动：

- **模块分工**：`context/` 负责团队知识工作台、代码关系图、平台入口、历史避坑与跨仓库 AI 编码红线（对应方案：[Team Context：给团队和 AI 用的团队工作台方案](/writing/team-context/)）。
- **雷达定位**：`radar/` 负责页面流向漏斗、元素点击与报错、上线变动对照、研发返工耗时与 AI 排查交接。
- **可选联动**：编译雷达时传入 `--context-dir context/data`，会自动按模块分工与文件名匹配 `owners.md`、`code-graph.json`、`pitfalls.md`，往 AI 排查包里补充对接人与历史避坑；不传该参数时 `radar/` 照常独立运行。

# 安全边界与落地节奏

工具本身跨公司带走，真实团队数据严格锁在公司内网，遵守 **公网与内网物理隔离** 原则：

- **公网只留脚本与虚构 Demo**：GitHub 上的 `team-kit` 仅包含零依赖 Python 脚本、通用方案与虚构示例；`data/`、`dist/`、`local-data/` 默认列入 `.gitignore`。
- **内网快照只留聚合统计**：`snapshot.json` 仅记录页面访问与转化率、耗时分位、埋点事件名、代码路径及小组级按期率，严禁写入用户隐私或个人绩效评价。

| 落地阶段 | 建议投入范围 | 关键产出 | 是否需审批平台接口 |
|-|-|-|-|
| 第 1 周：快跑通 | 用第一档导表填入核心页面转化、近期改动与耗时列表 | 编出首版四视图雷达，和同事对齐最急的 2–3 个卡点 | **不需要** |
| 第 2–4 周：半自动 | 补上本地只读 Git 扫描与定时汇总脚本，接入 `--context-dir` | 每周发版前固定生成一页对比，排查效率翻倍 | 基本不需要 |
| 长期：日常雷达 | 按条件接入第三档内部看板/APM/MCP 只读插件定时刷新 | 业务转化与技术指标每日同屏巡检，异常更早暴露 | 按内网规范只读申请 |

# 附录：快照结构与常用命令

`snapshot.json` 只需准备 4 段核心 JSON 数据，即可完整驱动交叉分析与四视图展示：

| 顶层字段 | 主要内容 | 说明 |
|-|-|-|
| `product_name` / `window` | 展示标题与对比时间窗口 | 例如当前灰度版本对比基线的时间范围 |
| `status_lights` | 顶部 4 格状态摘要 | 包含核心数值、简短说明与点击跳转目标 |
| `flow` | `nodes`（页面与交互元素）+ `edges` | 支撑转化、耗时、退回、改错与 3 组人群差异 |
| `timeline` / `engineering` | 日趋势 + 改动列表 + 小组按期率 + 热修与耗时 | 支撑上线变动对照与交付效率页签 |

```bash
# 1. 使用内置 Demo 生成交互看板（含 tokens 导出）
python3 radar/scripts/build_radar.py --input radar/examples/demo-radar.json --out dist/radar-demo.html --tokens-out dist/tokens.json

# 2. 列出重点问题，并导出单条上下文包交给 AI 排查
python3 radar/scripts/build_radar.py --input radar/examples/demo-radar.json --list-findings
python3 radar/scripts/build_radar.py --input radar/examples/demo-radar.json --export-prompt f_page_capture_tech

# 3. 联动 Team Context 数据目录生成看板（可选）
python3 radar/scripts/build_radar.py --input data/radar-snapshot.json --context-dir context/data --out dist/radar.html --tokens-out dist/tokens.json
```
